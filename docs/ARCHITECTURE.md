# Architecture

## Implemented frontend checkpoint

The repository is one Git project with a simple pnpm workspace. `client/` is a Next.js 16 App Router application. `server/` contains documentation only.

The frontend is organised by feature rather than by page-sized utility buckets:

- `app/` owns route groups, layouts, loading, error, and not-found boundaries.
- `components/` owns brand, shell, navigation, feedback, shared records, and shadcn-style primitives.
- `features/` owns authentication, cases, documents, workflow, timeline, contradictions, procedural audit, research, strategy, ethics, citations, motion, review, observability, audit, and settings.
- `lib/types` defines domain contracts.
- `lib/demo` owns closed fictional fixtures and the deterministic agent definition.
- `lib/api` owns request/response contracts, `LegalBridgeClient`, `MockLegalBridgeClient`, the intentionally unavailable `HttpLegalBridgeClient`, and query keys.
- `stores/` owns versioned Zustand state and guarded transitions.

Static shells and metadata remain server-rendered where useful. Interactive modules are isolated client components.

## State and data boundaries

Zustand is the authoritative state for this device-local demonstration: authentication flag, UI preferences, cases, document metadata, workflow progress, analysis fixtures, strategy and ethics status, motion versions, approval, export eligibility, and audit events. The persisted payload is versioned and can safely restore the seed case after an incompatible version.

The store never persists a password, review PIN, file binary, secret, or real personal record. Approval is derived from a saved motion version and deterministic mock hash. A meaningful saved edit creates a version, nulls approval, and inserts an invalidation event in the same transition.

TanStack Query is installed and provided as the future server-state boundary. The active client remains the deterministic mock adapter. `NEXT_PUBLIC_DATA_MODE` accepts only `mock`; an unsupported value produces a controlled configuration screen before the application renders.

## Deterministic workflow simulator

The workflow definition is separate from rendering and contains 15 fixed agents. Each node has a stable ID, description, input, output, source references, and seeded duration. The workflow component owns one cancellable timer at a time. Pause or unmount clears it; resume creates a single timer for the retained node. Store transitions prevent progress when status is not `running`.

Completion events are inserted only by explicit transitions, not component rendering, preventing refresh duplicates. The simulator performs no network, token, model, OCR, or legal-analysis call.

## Safety user interfaces

The Citation Firewall presents ten check categories and nine closed citation records. Its deterministic metrics are 9 resolved records, 9 verified quotations, 9 supported propositions, 0 phantom citations, and 0 unsupported final claims.

The Ethics review requires a visible rejection of the unsupported intentional-fabrication allegation. The motion fixture excludes that allegation. The attorney gate additionally requires reviewer name, demo PIN, responsibility acknowledgement, saved version, passing citations, and the applied rejection.

Export is browser print only. It remains disabled unless approval matches the latest saved version and mock hash. The print stylesheet hides navigation, includes approval metadata, and states that nothing is automatically filed.

## Audit and observability

Audit events are local, typed records generated by store actions. They cover authentication, case creation, documents, workflow controls and nodes, ethics actions, motion saves, approvals, invalidations, exports, and reset.

Observability values are closed synthetic metrics. Token counts, costs, tool calls, retry counts, durations, and time reduction are explicitly labelled simulated or estimated.

## Planned architecture, not implemented

A future FastAPI service may implement authenticated contracts; a LangGraph workflow may coordinate server-side agents; Gemini may provide model reasoning; Supabase PostgreSQL and pgvector may store relational and vector data; Supabase Storage may hold validated document objects; SSE may stream run events.

That future design must include tenant isolation, encrypted storage and transport, malware and file validation, prompt-injection controls, provenance-preserving extraction, retrieval from licensed legal sources, quotation and applicability verification, immutable audit records, and human approval enforcement on the server.

None of those backend, database, storage, model, retrieval, or streaming components exists in this checkpoint.
